# HairFlow 迭代记录

起始版本：1.2.0（初版交付）  
迭代目标：在不改变“原生 Curve 多段搭建、一次成笔”核心结构的前提下，围绕正确性、完整性、可读性、性能、边界情况、一致性完成两轮、共 43 轮实质改进（第 1–23 轮 + 第 24–43 轮）。  
最终版本：1.4.0

每一轮包含：优化目标 → 具体改动 → 改进理由 → 自检结果。

---

## 第 1 轮：Restore 的快照保护（正确性）

**优化目标**：避免用户在未执行 Remember 时点击 Restore，被写入一组默认值，反而破坏当前 Stroke 状态。

**具体改动**：

- 新增 `HF_HAS_SNAP` 状态变量；
- `Remember Stroke` 成功读取后置 1；
- `Restore Stroke` 改为 `If (HF_HAS_SNAP = 1)` 才写回；否则只提示“先按 Remember”。

**改进理由**：原实现把“恢复”做成了“无条件写入默认值”。这是正确性缺陷：用户可能只是想看看按钮作用，却把 Curve/Lazy 改了。

**自检**：插件在 2025.0.1 就地编译成功（10308 字节）；代码路径检查确认 Restore 的所有 `ISet` 都在快照判断内。

---
## 第 2 轮：模式按钮的核心路径保护（正确性 / 边界）

**优化目标**：当某个 ZBrush 版本没有 `Stroke:Curve` 或 `Stroke:Lazy Mouse` 时，按钮不能“看起来点了但什么都没发生”，更不能向不存在的控件写值。

**具体改动**：

- `Long Strand Curve` 外层增加 `IExists "Stroke:Curve"` 判断；
- 找不到 Curve 时显示明确提示，引导手动打开 Stroke > Curve；
- Freehand Assist 的 Curve / Lazy Mouse 也改为存在性判断后再写。

**改进理由**：原实现默认两条核心路径一定存在。2022/2025 都有，但不同小版本/精简安装可能缺项；静默失败比报错更难排查。

**自检**：2025 就地编译成功（10544 字节）；按钮动作现在只有 `IExists=1` 才执行 `ISet`。

---
## 第 3 轮：Preflight Check 预检按钮（边界情况）

**优化目标**：把“没有 SubTool / 不在 Edit 模式”这两个最常见的失败前置暴露，而不是让用户对空气搭曲线。

**具体改动**：

- 新增 `Preflight Check` 按钮；
- 依次检查 `SubToolGetCount`、`Transform:Edit`、Curve / Draw Size / Lazy；
- 三种结果分别给出可执行的提示：加载 PolyMesh、按 T 进入 Edit、或显示当前状态。

**改进理由**：Curve 在无模型/非 Edit 时不会产生可见结果，用户容易误判插件坏了。预检把排查从“猜”变成“读提示”。

**自检**：2025 就地编译成功（11052 字节）；嵌套 `If` 的三种分支都在按钮动作内。

---
## 第 4 轮：Curve Functions 的回退提示（正确性 / 可读性）

**优化目标**：当 Add/Smooth/Delete 路径在某个版本缺失时，按钮不再“静默无反应”，而是告诉用户去哪里手动完成。

**具体改动**：

- 三个按钮的 `IExists` 判断都补上 `Else` 分支；
- 缺失时用 NoteBar 指向 `Stroke > Curve Functions > 同名功能`；
- tooltip 补充 “Requires an active curve”。

**改进理由**：原实现只做 `If`，路径缺失时点按钮毫无反馈，用户会怀疑插件损坏；同时“需要先有曲线”这一前提没有写在悬停说明里。

**自检**：2025 就地编译成功（11412 字节）；三个按钮均具备成功/回退两条路径。

---
## 第 5 轮：按真实工作流重排按钮（一致性 / 可用性）

**优化目标**：让面板从上到下就是用户的操作顺序，减少在“模式/工具/记忆”之间来回找按钮。

**具体改动**：

- 新顺序：Preflight → Long Strand → Add → Smooth → Delete → Step 2/5/10 → Snap On/Off → Freehand → Remember → Restore → Diagnostics → Workflow；
- 只改 UI 定义顺序，不改任何按钮动作或路径。

**改进理由**：原顺序把 Freehand / Snap / Step 放在 Add/Smooth/Delete 之前，和“先搭曲线再修曲线”的实际流程相反；按钮多时顺序就是隐性说明书。

**自检**：2025 就地编译成功（11416 字节）；`grep '^[IButton'` 确认 15 个按钮按目标顺序排列，无重复/丢失。

## 第 6 轮：补充 Curve Step 1 与性能分层（性能 / 完整性）

**优化目标**：给“极细发丝”一个比 2 更密的档位，同时明确不同发束长度下该用哪一档，避免用户全程用 1 把 ZBrush 拖死。

**具体改动**：

- 新增 `Curve Step 1` 按钮（范围 0–10 内合法）；
- README 参数表增加 1 档；
- 增加按发束长度选择 Step 的经验规则：>2 头长先 5/10，>4 头长优先 10，只在局部用 1。

**改进理由**：原 2/5/10 缺少“极细”档；同时没有把性能和发束长度关联，用户容易在长曲线上用最小 Step 导致每次加点都重算大量 stamp。

**自检**：2025 就地编译成功（11668 字节）；Step 1 的 `ISet` 仍在 `IExists` 保护内；文档表格与按钮值一致。

## 第 7 轮：Diagnostics 写入结果校验（正确性 / 边界）

**优化目标**：当 `C:/HairFlow` 不存在或不可写时，Diagnostics 不能仍然报“已写入”。

**具体改动**：

- 新增 `HF_DIAGOK` 变量；
- 把 `MemSaveToFile` 的返回值存入 `HF_DIAGOK`；
- 成功/失败分别给不同 NoteBar，失败时提示检查目录存在与可写。

**改进理由**：原实现无条件提示成功，是典型的“假成功”；用户拿着不存在的日志排查会浪费更多时间。

**自检**：2025 就地编译成功（11828 字节）；`MemSaveToFile` 返回值现在参与分支。

**自检**：2025 就地编译成功（11968 字节）；路径与安装脚本创建的数据目录一致。

## 第 12 轮：版本号统一为 1.3.0（一致性）

**优化目标**：让插件、文档、安装脚本、诊断输出使用同一个版本号，避免“文档 1.2、插件 1.3”的错位。

**具体改动**：

**自检**：`grep -rn "1\.2"` 在插件与主要文档中不再命中（CHANGELOG 历史除外）；2025 就地编译成功（11968 字节）。

## 第 13 轮：术语表（可读性）

**自检**：术语与 README 第 4/5 节、FAQ 中的用法一致；没有新增未实现的按钮。

## 第 14 轮：明确“不做什么”（完整性 / 期望管理）

**优化目标**：把插件的能力边界写清楚，避免用户以为它能自动焊接自由笔划、或能恢复笔刷全部参数。

**具体改动**：

**改进理由**：功能说明只讲“能做什么”容易让用户产生错误预期；边界说明能减少误用和“为什么不做 X”的重复沟通。

**自检**：五条“不做”与插件源码一致（无 CanvasStroke、无笔刷参数 ISet、无文件网格 IO、无后台进程）。

## 第 16 轮：安装脚本健壮性（正确性 / 边界）

**优化目标**：安装脚本在源文件缺失、ZBrush 目录不存在、首次安装没有旧文件时，行为要可预测，不能抛半截错误或创建空备份。

**具体改动**：

- 先检查 ZBrush 根目录、`ZPlugs64`、源 `HairFlow.txt`，缺失时明确跳过/报错；
- 只有存在旧 `HairFlow.txt` / `.zsc` 时才创建备份目录；
- 复制后打印目标文件实际字节数，作为“确实写入”的证据；
- 去掉函数末尾对可能未定义 `$backup` 的引用。

**改进理由**：原脚本无条件建备份目录、无条件复制；源文件缺失时会抛异常但前面可能已经创建空目录，排查时容易误判。

**自检**：在临时 Fake2025/Fake2022 目录连续运行两次：第一次“无旧文件”分支正常，第二次“备份”分支正常；目标文件均为 8096 字节，无异常终止。

## 第 17 轮：静态检查脚本（验证可重复性）

**优化目标**：把“插件源码/文档有没有回归”变成一条可重复执行的命令，而不是每次靠肉眼。

**具体改动**：

**自检**：首次运行发现 README 缺少 `Preflight Check` 条目；补齐后重跑 **RESULT: PASS**（17 个按钮全部覆盖）。这是一次脚本真实发现并修复问题的记录。

## 第 18 轮：性能与长曲线策略（性能 / 边界）

**优化目标**：让用户在长发束变卡时有明确的降级顺序，并且不为了性能破坏“同一条曲线”的核心原则。

**具体改动**：

- 新增 7.1 节“性能与长曲线”；
- 给出成本模型：成本 ≈ 曲线长度 ÷ Curve Step；
- 按发束长度给出 Step 推荐表（<1、1–2、2–4、>4 头长）；
- 明确“不要为了省性能把同一条发束拆成两条曲线”，否则接缝回归；
- 给出卡顿时的四步降级顺序。

**改进理由**：前一版只说了“Step 小更慢”，没有把“长度 × Step”的成本说透，也没有阻止用户用拆曲线来换性能。

**自检**：推荐表与 5.1 的 Step 档位一致；没有建议拆分同一条发束；与核心“one curve, one stroke”不冲突。

## 第 44 轮（接手审查）：原生路径身份实测与核心修正 → 1.5.0

**优化目标**：前 43 轮的“验证”都以 `IExists=1` 为准。接手后先质疑这个前提：`IExists` 只说明“能找到点什么”，不说明“找到的就是想要的控件”。

**方法**：在 2025.0.1 启动期运行只读探针（Macros 目录，启动时编译执行），对每个插件路径取 `IGetID` / `IGetTitle` / `IGet` / `IGetMin` / `IGetMax`，并按 id 枚举 Curve 子面板全部成员（`tests/results/stroke_paths_2025.txt`）。

**发现**：

- `Stroke:Curve` 是子面板（id 11277），真正开关是 `Stroke:Curve:Curve Mode`（id 1239）。旧 Long Strand Curve 写入后 Curve Mode 仍为 0——**主按钮从未打开曲线模式**；
- `Stroke:Curve Functions` 子面板不存在（`IGetID` 报错），但 `IExists "Stroke:Curve Functions:Add"` 返回 1，并解析为 `Stroke:Inventory:Add`；
- Curve Step 默认 0.25、范围 0–10、越小越密，旧预设语义反了；Lazy Smooth 上限 16；Lazy 启动值 1 / 0.25 / 0；
- `ZPlugs64` 里的 `.txt` 不会被自动编译；脚本 `IPress` 自定义按钮会接管执行、调用方中断（解释了旧记录里的“退出”）；脚本 `ISet` 滑杆不触发其回调。

**改动**：见 CHANGELOG 1.5.0。核心：全部改用实测路径；删除错误的 Add 按钮；Curve Step 预设改为 0.1/0.25/0.5/1 并同步滑杆；Lazy 值改为合法值；变量名去下划线；诊断去 NUL。

**新的验证手段**：

- `tests/build_runtime_test.py` 从源码原样抽取按钮命令体 → 逐个执行回读（15 步全部符合，Restore 后逐项回到初值）；
- `tests/probe_ui.txt` 增加路径身份校验（9/9 解析正确）；
- `check_hairflow.py` 增加白名单/范围/命名检查，并确认能抓出 1.4.0 的全部问题。

**自检**：2025 编译 14800 字节自动加载、20 按钮 + 滑杆存在；静态检查 PASS；安装校验 PASS。仍需手工：真人拖动滑杆、点击曲线提交、端点拖动的原生手感（ACCEPTANCE B9 / C2–C6 / C3b）。

**教训**：“探针全部 =1”不是验证，只是存在性检查。验证要回读**效果**（写入后 Curve Mode 是否变 1），并确认**身份**（路径解析到哪个控件）。

## 第 45 轮（屏幕实测）：拖曲线会雕刻 → Shape Lock → 1.6.0

**优化目标**：用户要求不靠人工、直接用屏幕控制验证。把文档里“只能手工”的项全部实际操作一遍。

**方法**：Computer Use 操作 ZBrush 2025.0.1 与 2022.0.5：建 52 万面球体、DamStandard，在球面不同区域做对照实验（A–G，见 VERIFICATION 2.5），每次 Delete Curve 后放大检查。

**发现**：

- 拖曲线（中段或端点）会在每个鼠标移动时沿曲线压一次——1.5.0 文档的“拖曲线调形、最后点一次提交”会叠出多排痕迹；
- 端点拖动 = 移动整条曲线，不能接长；点一下曲线 = 压一次（静止合成点击不触发，1 像素移动即触发）；Smooth 不雕刻；
- Step 0.25 下 DamStandard 呈珠串，0.1 连续；
- “曲线函数”子面板在界面中存在（删除/快照/平滑），只是脚本按名字查不到；快照在 DamStandard 下禁用；
- 2022 的 “Unable To Open File” 只在 2025 同时运行时出现；关掉 2025 后 2022 正常，可以做完整验证。

**改动**：Shape Lock / Shape Unlock（关/还原 Zadd、Zsub，Z 强度不动，重复 Lock 安全，Restore/Reset 兜底解锁）；Long Strand Curve 默认 Step 0.1；提示与文档改为实测流程；2022 自编译 `.zsc` 入包并由安装脚本分别安装；校验脚本核对两版。

**自检**：两版 UI/路径探针一致（22 按钮、12 路径）；两版 19 步命令体回读逐行相同；两版屏幕端到端：调形无痕、提交得到单条连续收尖沟、Restore 回到初值；静态检查 PASS；安装校验 28 项 PASS。

**教训**：运行期“回读参数正确”仍不等于“用户流程正确”。只有真的在模型上画一遍，才会发现拖曲线本身在雕刻。
